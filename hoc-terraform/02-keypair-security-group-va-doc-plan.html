1 · Lý thuyết nền — Terraform nghĩ như thế nào

IaC (Infrastructure as Code) là tư tưởng: hạ tầng (máy chủ, firewall, mạng…) được mô tả bằng file text thay vì click chuột. File text thì diff được, review được, lưu lên Git được, và tạo lại y hệt ở nơi khác được.

Terraform là "khai" chứ không phải "lệnh" (declarative vs imperative)

Cách nghĩVí dụ
Imperative (lệnh)Viết từng bước làm — như đầu bếp đọc công thứcaws ec2 run-instances --image-id ami-... --count 1
Declarative (khai — Terraform)Viết kết quả mong muốn — như đặt món, đầu bếp tự lo thứ tựresource "aws_instance" "example" { ... }
Bạn không bao giờ bảo Terraform "hãy tạo key trước, rồi tạo SG, rồi tạo máy". Bạn chỉ khai báo máy dùng key và SG — thứ tự suy ra từ đó.

Khoản khắc cốt lõi: 3 "trạng thái"

TênLà gìNằm ở đâu trong project của bạn
Desired state
(muốn là)		Mô tả hạ tầng bạn viếtmain.tf
Actual state
(thực tế là)		Hạ tầng đang tồn tại trên AWStrên vùng ap-southeast-2
Recorded state
(ghi nhớ là)		Bản ghi "Terraform nghĩ thực tế là gì", kèm ID AWS của từng resourceterraform.tfstate
Mọi lệnh Terraform đều xoay quanh 3 cái này:
• plan = so muốn với ghi nhớ (có hỏi AWS để cập nhật ghi nhớ cho khỏi sai lệch)
• điểm chết của Terraform: nếu ai đó lên AWS console xóa máy tay, và tfstate vẫn ghi còn → nó "tưởng" mọi thứ ổn. Vì vậy luôn chạy plan (tự refresh) trước khi tin bất cứ điều gì.

Tính idempotent — "chạy bao nhiêu lần cũng ra một kết quả"

apply lần 1: tạo mới 3 resource. apply lần 2: 0 thay đổi. Đây không phải coincidence — là thiết kế: hệ thống luôn bị kéo về đúng mô tả. Kết quả plan ra "No changes" chính là bằng chứng trạng thái đã "hội tụ" (converged).

2 · Cú pháp HCL trong 1 phút

HCL = ngôn ngữ của Terraform. Chỉ cần hiểu đúng 2 cấu trúc: 
# CẤU TRÚC 1: BLOCK — "một vật thể có tên"
loại "kiểu" "nhãn" {
  thuộc_tính = "giá trị"
}
# vd: resource "aws_instance" "example" { ... }
#     ^động từ  ^kiểu (AWS gì?)  ^tên DO BẠN ĐẶT

# CẤU TRÚC 2: GIÁ TRỊ
chuỗi   = "text"
số      = 22
boolean = true
danh sách = [1, 2, 3]      # [] = list — thứ tự, lặp được
bản đồ   = { Key = "Value" } # {} = map — tra bằng tên

# THAM CHIẾU: trỏ tới "nhà hàng xóm"
aws_key_pair.learn_terraform_key.key_name
#  ^kiểu         ^nhãn            ^thuộc tính lấy ra

# HÀM: file() đọc nội dung file lúc plan
public_key = file("/home/nguyenhungvy09/.ssh/devops-learn.pub")

3 · Giải thích từng dòng main.tf

🧭 Provider — "Terraform sẽ chơi với cloud nào"

 1provider "aws" {
 2  region  = "ap-southeast-2"
 3}
DòngGiải thích
1Block provider = khai báo plugin điều khiển cloud nào. "aws" là tên plugin (HashiCorp viết sẵn, terraform init đã tải về — nằm trong thư mục .terraform/). Một file có thể khai nhiều provider (aws + cloudflare + google…).
2region = vùng địa lý数据中心 của AWS sẽ nhận mọi lệnh. ap-southeast-2 = Sydney. Điểm sống còn Mọi ID (AMI, subnet…) chỉ đúng trong một region duy nhất — đó là lý do bạn từng gặp lỗi InvalidAMIID.NotFound.
3Đóng block.

🔎 Data source — "tra cứu cái đã có, không tạo mới"

 5# data source = "đọc thứ CÓ SẴN trên AWS" (khác resource = "tạo mới")
 6# default VPC đã tồn tại sẵn trong tài khoản -> chỉ việc tra cứu ID của nó
 7data "aws_vpc" "default" {
 8  default = true
 9}
DòngGiải thích
7data = từ khóa đối lập với resource: "tài nguyên này KHÔNG do ta tạo, hãy đi đọc thông tin của nó về". Kiểu aws_vpc = "VPC của AWS"; nhãn "default" do bạn đặt. Địa chỉ đầy đủ: data.aws_vpc.default.
8default = true là điều kiện lọc khi tra: "tìm cho tôi VPC được đánh dấu là mặc định". Mỗi region có đúng một cái, AWS tự tạo khi bạn mở tài khoản.
→Sau khi đọc, nó xuất ra nhiều thuộc tính: .id (= vpc-0bb52fcbdd46b2066 — bạn thấy dòng này trong plan), .cidr_block, .arn… Dòng 33 dùng .id.

🖥️ Resource chính — cái máy chủ EC2

11resource "aws_instance" "example" {
12  ami           = "ami-048cdccbe32bcb9a8"
13  instance_type = "t3.micro"
14
15  # 2 dòng này "lắp" key và SG vào instance:
16  key_name               = aws_key_pair.learn_terraform_key.key_name
17  vpc_security_group_ids = [aws_security_group.learn_terraform_sg.id]
18
19  tags = {
20    Name = "ExampleInstance"
21  }
22}
DòngGiải thích
11resource = "tạo mới". Kiểu aws_instance = "một máy EC2"; nhãn "example" do bạn đặt. Quan trọng Cặp aws_instance.example là địa chỉ duy nhất trong Terraform — dùng trong terraform state show aws_instance.example, -target=.... Nó KHÔNG liên quan gì tới ID thật của AWS (i-056f...) — Terraform giữ ánh xạ "địa chỉ ↔ ID AWS" trong tfstate. Đổi nhãn = Terraform tưởng là resource khác (xóa cái cũ tạo cái mới!).
12ami = Amazon Machine Image — "bản cài Windows" của máy: chứa OS, driver, cloud-init. ID này là bản Amazon Linux 2023 ở region Sydney. AMI ID không xài chéo region.
13instance_type = cấu hình phần cứng (số vCPU, RAM). t3.micro = 2 vCPU siêu nhỏ / 1GB RAM — hạng Free Tier. Dòng t = "burstable" (chạy nhỏ giá rẻ, lúc cần burst CPU — bạn thấy credit_specification trong show).
16Tham chiếu: "lấy key_name của cái key pair ở dòng 24". Máy chỉ SSH được nếu boot với key. forces replacement Đổi giá trị này trên máy đang chạy = AWS không cho → Terraform đập máy cũ tạo máy mới (bạn đã chứng kiến tận mắt).
17list các SG (dấu [] là vì có thể gắn nhiều SG — luật của mọi SG cộng dồn). Ở đây một SG. Đây là SG kiểu VPC, nên trường tên là vpc_....
19–21tags = map nhãn dán lên resource trên AWS. Không ảnh hưởng vận hành, nhưng là nhãn để tìm & phân bổ chi phí ("máy này của dự án nào? ai trả tiền?"). Cột Name hiện sẵn ở EC2 console.

🔑 Key pair — chìa khóa SSH

24resource "aws_key_pair" "learn_terraform_key" {
25  key_name   = "learn_terraform_key"
26  # Terraform KHÔNG hiểu "~" phải viết đường dẫn tuyệt đối đầy đủ:
27  public_key = file("/home/nguyenhungvy09/.ssh/devops-learn.pub")
28}
DòngGiải thích
24Resource kiểu aws_key_pair = "một public key được đăng ký trong tài khoản AWS".
25key_name = tên key trên AWS (khác với dòng 16: dòng đó nói "máy này dùng key tên gì").instance được gắn key nào thì đúng public key đó mới SSH được.
27public_key = nội dung chìa công khai. Hàm file() đọc nó từ đĩa v lúc chạy plan (vì vậy plan in ra nguyên chuỗi ssh-ed25519 AAAA...). Lý do an toàn của cả cơ chế: AWS chỉ giữ public; private key không rời máy bạn — chưa từng gửi cho ai, kể cả AWS.

🛡️ Security Group — firewall cấp máy

30resource "aws_security_group" "learn_terraform_sg" {
31  name        = "learn-terraform-sg"
32  description = "SG for learning"
33  vpc_id      = data.aws_vpc.default.id
34
35  ingress {
36    description = "SSH"
37    from_port   = 22
38    to_port     = 22
39    protocol    = "tcp"
40    cidr_blocks = ["113.23.122.254/32"]
41  }
42
43  egress {
44    description = "all outbound"
45    from_port   = 0
46    to_port     = 0
47    protocol    = "-1"
48    cidr_blocks = ["0.0.0.0/0"]
49  }
50  tags = {
51    Name = "learn-terraform"
52  }
53}
DòngGiải thích
31Tên SG — phải duy nhất trong một VPC (đó là lý do cần dòng 33).
32Mô tả — cẩn thận trên AWS, description của SG không sửa được sau khi tạo (đổi = tạo SG mới).
33Nhúng SG vào đúng VPC, đọc từ data source dòng 7. Không khai báo dòng này thì AWS đặt vào default VPC — may mà đúng, nhưng code "ăn may" là code nợ.
35–41Một block ingress = MỘT rule cho phép đi VÀO. Đọc tiếng người: "Cho phép giao thức TCP, chỉ port 22 (from=to=22), chỉ từ đúng IP 113.23.122.254 (/32 = một IP duy nhất), đi vào máy của ta."
37–38Khoảng port. 1 port duy nhất → hai vế bằng nhau. (Mở web: 80; HTTPS: 443; dải 8000–8100 → from=8000 to=8100.)
39"tcp" — SSH chạy trên TCP. Các giá trị: tcp, udp, "-1".
40List CIDR nguồn được phép. /32 = đúng 1 IP; /24 = 256 IP; /0 = mọi IP. IP của bạn là IP động của nhà mạng — đổi nhà mạng/diễn lại là mất SSH 😄.
43–49Rule cho traffic đi RA. Công thức "mở hết": protocol -1 (mọi giao thức) + port 0–0 + 0.0.0.0/0 (mọi đích). Vì sao bắt buộc phải viết? — vì SG mới của AWS mặc định chặn toàn bộ chiều ra. Không có nó: không tải package, không cập nhật, không gọi API. Không có dòng = không được phép.
50–52Nhãn cho SG — tìm bằng terraform state list, và hiển thị trên console.
Nhận xét "code review" file hiện tại (chưa cần sửa ngay, biết để trưởng thành):
• Thiếu rule ingress port 80 → bài 3 dựng web sẽ phải thêm (và SG thêm rule tại chỗ, không replace máy — khác key_name!).
• root_block_device { encrypted = true } nên thêm sau này — disk hiện chưa mã hóa.
• IP trong CIDR là giá trị "cứng" — sẽ học tham số hóa bằng variable ở bài sau.

5 · Từ điển bỏ túi

Thuật ngữNghĩa thuần Việt
providerPlugin điều khiển một cloud/dịch vụ (aws, google, cloudflare…). Terraform vốn "mù" về AWS — provider mới biết.
resourceMột thứ bạn muốn tồn tại: máy, key, SG… Cú pháp: resource "kiểu" "nhãn".
data sourceMột thứ đã tồn tại, chỉ đọc thông tin (id, cidr…).
argumentThuộc tính bạn viết trong cấu hình (ami, region…).
attributeThuộc tính AWS trả về — có loại đọc tham chiếu được (.id, .arn, .public_ip).
referenceViết loại.nhãn.attribute để "nối" resource — Terraform dịch thành thứ tự tạo.
state fileterraform.tfstate — bộ nhớ của Terraform: ánh xạ "địa chỉ trong code ↔ ID thật trên AWS". Mất nó = Terraform không còn biết tài nguyên của mình là gì.
plan / applyplan = tính và in "sẽ làm gì" (không làm). apply = làm thật (hiện plan, hỏi yes).
destroy = tính và xóa mọi resource Terraform đang quản lý.
(known after apply)Chưa thể biết giá trị (AWS chưa tạo) — không phải thay đổi bạn yêu cầu.
forces replacementAWS không cho đổi tại chỗ → phải đập đi tạo lại. Đọc trước khi apply như đọc hợp đồng.
VPC / subnet / AZVPC = mạng riêng của bạn trong AWS. Subnet = một dải IP con trong VPC. AZ (ap-southeast-2b) = một khu vực vật lý riêng.
Security GroupFirewall gắn vào máy, chỉ có rule cho phép (whitelist), ingress vào / egress ra.
AMIBản OS + chuẩn bị boot. ID chỉ có hiệu lực trong region chứa nó.
CIDR /32Cách viết "một dải IP" — hậu tố càng nhỏ dải càng lớn. /32 = 1 IP, /24 = 256 IP, 0.0.0.0/0 = tất cả.
public / private IPPublic = nhìn từ internet (đổi khi máy bị tạo lại). Private = IP nội bộ VPC (mọi máy khác trong VPC nhìn thấy).
SSH key pairCặp khóa: private giữ lại máy bạn, công khai lên AWS. SSH = hai bên chứng minh khớp khóa — không mật khẩu.
cloud-initTrình chạy lúc máy boot lần đầu: đọc key, chạy script user_data — log ở /var/log/cloud-init-output.log.

6 · Tự kiểm tra (10 câu)

Nhấp từng câu để xem đáp án. Trả lời được hết = nắm vững file này.

1. Nhãn "example" đổi thành "new" thì điều gì xảy ra? Terraform coi đó là resource khác hoàn toàn → destroy máy cũ + create máy mới (dù nội dung không đổi). Địa chỉ trong code là danh tính thật của resource đối với Terraform.
2. terraform.tfstate là gì và vì sao không được làm mất? Bản ghi trạng thái + ánh xạ địa chỉ→ID AWS. Mất nó → Terraform không biết tài nguyên thật là cái nào, không xóa/cập nhật được, plan sẽ đòi tạo lại mọi thứ (hoặc phải import).
3. Vì sao region làm lỗi InvalidAMIID.NotFound? AMI ID chỉ tồn tại trong region chứa nó. ami-04f5... ở region khác, không có ở ap-southeast-2 → "does not exist".
4. data khác resource ở điểm nào? Nêu 2 ví dụ trong file. resource = tạo mới (aws_instance, aws_key_pair, aws_security_group). data = tra cứu cái có sẵn (aws_vpc default — không tạo VPC, chỉ đọc ID của nó).
5. SG mới tạo trên AWS mặc định cho traffic ra/vao thế nào? Chặn TẤT CẢ cả vào lẫn ra. Mọi thứ thông đều phải do rule cho phép (whitelist).
6. cidr_blocks = ["1.2.3.4/32"] nghĩa là gì? /24 thì sao? /32 = đúng 1 IP. /24 = cả dải 1.2.3.0–1.2.3.255 (256 IP). 0.0.0.0/0 = mọi IP trên internet.
7. Vì sao đổi key_name phải đập máy, còn đổi tag thì không? Key được cloud-init tiêm lúc boot — máy đang chạy không tiêm lại được. Tag chỉ là nhãn metadata trên AWS, sửa tại chỗ (update in-place). Đọc plan sẽ thấy: tag → ~ update, key → -/+ replace.
8. "(known after apply)" là gì? Có phải thay đổi bạn yêu cầu không? Là giá trị do AWS sinh ra mà chưa tạo nên chưa biết (IP, ARN, volume id…). KHÔNG phải ý định của bạn — mẹo đọc plan: lọc hết dòng known after apply, phần còn lại mới là thay đổi thật.
9. 2 tham số SSH của dòng lệnh ssh? -i là gì? ssh -i ~/.ssh/devops-learn ec2-user@13.239.43.200 — -i = private key dùng để chứng minh danh tính; ec2-user = user mặc định của Amazon Linux (Ubuntu dùng "ubuntu").
10. Nếu có người xóa máy EC2 ngay trên AWS console (tay), chạy terraform plan thì sao? Plan sẽ refresh, phát hiện trong state ghi còn mà AWS không còn → báo recreate máy (phát hiện "drift"). Bài học: luôn plan trước khi apply, và đừng sửa tay trên tài nguyên Terraform quản lý.
